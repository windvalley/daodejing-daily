# AI 助手「问道」

这份文档说明 AI 功能的边界、数据流向与实现位置。
功能本身是可选的：不配置就用不了，配置之后也不影响离线阅读、背诵与复习。

## 定位

全站只有一个入口，叫「问道」。它回答三类问题：

- 这一章某句怎么理解，某个字为什么这样读。
- 这一章和另一章、某个核心概念是什么关系。
- 这一章的内容放到具体的处境里，可以怎么做。

入口不新增路由。所有断点共用一个右下角悬浮球，只有底部边距随断点变（窄屏要避开底栏）：
球上写「问」，鼠标悬停或用键盘聚焦时补出「道」，触屏保持一个字；滚动时收起，停下后重新出现。
不单独开一个 `/ask` 页面的原因有两个：做成路由会丢掉「当前停在哪一章」，也会打断朗读、默写这些带状态的页面。

面板的关闭有两个落点：右上角的关闭按钮，和面板底部的「收起」。
后者是单手操作的主力：面板随对话变长最高撑到 `84vh`，此时右上角已抬到屏幕上半部，只有底部这一颗还在拇指区。
配置好之后它落在输入框下方的左下角，未配置的引导页没有输入框，就在「去配置」旁边补一颗。
不接管全屏下滑关闭：下移正是「回看前面回答」的动作，绑在正文上会把想回看的人关掉面板。

## 上下文

模型拿到的材料分两层。

| 层   | 内容                                             | 位置      | 规模         |
| ---- | ------------------------------------------------ | --------- | ------------ |
| 全书 | 八十一章的章题、原文、章旨、译文、注释、实践提示 | system    | 约 2.3 万字  |
| 焦点 | 当前章节号、选中句、该句逐字注音与释义           | 末条 user | 几十到几百字 |

全书放进 system 而不是「只发当前章」，有三个理由。

1. 跨章提问是正常用法。概念页里「德」关联二十六章，读者一定会问「这和第 8 章的水是不是一回事」。只给当前章，模型不会承认自己没材料，它会用训练记忆补一个听起来合理的答案。
2. 固定前缀能命中厂商的上下文缓存。按章换前缀等于每次都全价。
3. 全书都在前缀里，不需要检索层，省掉召回排序与「检索漏了」这一整类问题。

代价是首次请求约 70KB 上行。设置里给一个「省流模式」，默认关闭。

打开后 system 只剩提示词规则，材料全部由焦点块提供：章页只发当前这一章，概念页只发概览、引文与关联章号，不附章节正文。
一句话，除了当前定位的章节，别的内容一个字都不发。代价是跨章提问会答不好，这是读者为了省流量主动选的。

## 联网搜索

设置里有一项「允许联网搜索」，默认关闭。

开启后请求体带 `tools: [{"type": "deepseek_web_search"}]`，由 DeepSeek 服务端执行检索并回传引用，
客户端不需要自己接搜索 API。工具名是 DeepSeek 专有的：照 OpenAI 写成 `web_search` 会被 422 拒绝。

回答以「书内」「书外」分开表述为合格标准。实测对比同一个问题：

- 关闭时：`server_tool_use` 为空，回答先讲本书训释，再说明「今天常用义……是我凭既有知识补充的，不是本书内容」。
- 开启时：`server_tool_use` 显示检索两次，回答明确区分「书内第 4 章注释」与「书外现代汉语」，
  并指出贬义色彩是后起的流变。

代价是实测在同一问题上 prompt_tokens 从约 2.4 万涨到约 5.2 万（检索结果本身也占上下文），
所以默认关闭，由读者按需打开。

这个开关只影响「问书外的事」。书的训释始终以材料为准，联网结果不会被用来改写章文与注释。

## 提示词约束

写进 system，作为常量 `AI_RULES`，可被测试断言。

- 材料分级：全书是材料，当前章节是主材料；回答要说明依据哪一章。
- 训释分歧照实说：注释里已经并存两读的（如第 1 章「常无欲，常有欲」），必须并列呈现，不替读者裁决。
- 读音以数据为准：涉及读音时与注音数据一致，数据的 `hint` 优先。
- 长度与排版：默认三句以内，可以用粗体、短列表与小标题；不堆表格与代码块，读者明确要求展开才放宽长度。
- 不确定就说不知道；不要编造章句与出处。

联网与否用两套互斥的规则，按设置里的开关选一。

- 关闭（默认）：「没有联网与检索能力，读者要求联网时直接说明做不到，不要假装查过」。
- 开启：「你有联网搜索工具，**默认就该用**」，并划清什么时候算材料不够，同时要求「联网内容必须与本书分开说明」「冲突时以本书为准」。

两套必须互斥。早先只写了「你没有联网能力」这一条，结果开着联网工具也答「我没法联网」，
因为提示词压过了工具。反过来只写「可以联网」而不写分离要求，网上说法会混进本书训释里，
这正是这个应用最不能接受的失败。

### 为什么写成「默认就该用」

写成许可（「你可以调用联网搜索」）时，模型看到材料里有点相关就直接作答，不会主动去查。
真机上的表现是：问「为什么是『和其光』不是『藏其光』」，第 56 章只注了「含藏光芒，混同尘世」，
模型答完就停，还主动说「材料只说到这一层」，却不去搜。

改成缺省动作并给出判据后，同一批问题稳定触发检索：

| 问题                             | 改写前 | 改写后    |
| -------------------------------- | ------ | --------- |
| 「玄同」到底是什么意思           | 未联网 | 联网 3 次 |
| 为什么是「和其光」不是「藏其光」 | 未联网 | 联网 4 次 |
| 这里为什么用「尘」这个字         | 未联网 | 联网 4 次 |

判据要具体到能自查，不能只说「必要时」。列出来源类型（字义、出处、异文、注家分歧、读音、典故、名物、史实、后世用法）
比「材料不够时」有用得多，因为后者要靠模型自己判断「够不够」，而它倾向于认为够。

同时保留一条「检索后仍然没有可靠答案，就说没查到」：放开检索后模型更容易编，
这条是防止它用印象补足的最后一道。

## 引用校验

回答里凡出现「第 N 章」或引号中的片段，抽出来用 `normalize` 去标点后，在各章原文里做子串匹配。
校验分两层：

- 存在性：这段文字在书里找得到吗。
- 归属：找得到的话，是不是回答说的那一章。

两条都过才照常显示，章号变成可点链接。任一不过就在回答下方标注：

- 找不到：「有 N 处引文未在书中找到」。
- 章号写错：「有 N 处引文的章号对不上」。

第二层是必须的。只查存在性时，「第四十二章说『上善若水，水善利万物而不争』」会被判为通过，
界面还会把这个错章号渲染成可点的「依据」链接，等于替错误背书。

归属判定要容许多章命中。同一句话可能同时出现在几章，例如「和光同尘」在第 4 章与第 56 章的注释里都有，
「知止」在第三十二章与第四十四章都有。只认第一个命中的章，会把读者引第 56 章的正确说法判成写错。
现在收集全部命中章，只要包含回答说的那一章就不算错。

「X 是第 N 章 Y 的意思」这类句子讲的是释义关系，不是出处声明，不参与归属判定，
否则「『适可而止』是第 9 章『持而盈之』的意思」会因为「适可而止」在第三十二章译文里出现而被误报。

章号的位置有两种，都要认：

- 后置：「『道法自然』出自第 25 章」。只认「出自、语出、见于、出于、载于、见、在、即、是、约」这类实词连接，
  光隔一个逗号不算，否则「『上善若水』，第 42 章讲的是另一回事」会被误读成前一句出自第 42 章。
- 前置：「第 8 章说『上善若水』」。只在同一句里认，跨句去猜会把
  「第四十二章讲万物生成。『上善若水』另说一层」这类正常写法误判。

两处都有时以后置为准。真实模型的回答里出现过「『道法自然』出自第 25 章，『不为而成』出自第 47 章」，
只往前找会把后者错配成第 25 章，于是把一句正确的回答报成出处错误。
引号里少于四个字、或汉字少于三个的片段不参与校验，避免把「无为」这类术语判成编造。

比对范围是整章材料（原文、译文、章旨、注释、实践提示），不只是原文，另外允许省略式引用。
这两条来自真实模型的回答：它引了第 8 章注释里的「最高的善」，又把第 81 章隔着「圣人之道」的两截并进一个引号。
只查原文整串会让这两种正常引法报「未找到」，读者只会觉得这个提示是坏的。
把两章的句子并进同一个引号仍然判为找不到。

## 回答排版

回答按最小 Markdown 子集渲染，不把 `###`、`**` 这类符号直接露给读者。

先前只靠提示词要求纯文本，实测守住不住：读者一问「是否建议全文背诵」，模型就会给出标题加要点列表，符号全部落在气泡里。

支持的范围只有读回答时真正会遇到的那几类，多一类都不加：

- 块级：段落、ATX 标题、无序与有序列表（缩进层级保留）、引用、围栏代码块、分隔线。
- 行内：`**粗体**`、`*斜体*`、三个星号的粗斜体、反引号代码、反斜杠转义，以及 `文字（地址）` 形式的链接改写。

解析写在 `src/lib/aiMarkdown.ts`，是纯函数，输出节点树；`src/components/AiMarkdown.tsx` 只负责把节点变成 React 元素。
**不用 `dangerouslySetInnerHTML`**：回答由模型生成，一旦当 HTML 插进页面，提示被注入或服务被换掉都可能直接改写界面。
模型返回的 `<img onerror=…>` 这类标签只会以文字出现，测试锁住了这一条。

几处刻意的取舍：

- **单换行保留，只有空行才分段**。纯文本时代靠 `white-space: pre-wrap` 保留换行；解析时若把单换行并成一段，
  模型用「1、」「（1）」「•」这类非 ASCII 编号写的要点会被并成一整行，比原样显示还难读。换行由渲染层的 `<br>` 承载。
- 列表只认 ASCII 的 `-`、`*`、`+` 与 `1.`、`1)` 写法。中文顿号、全角括号编号不解析成列表，但保留分行。
- 表格、图片、脚注、原始 HTML 都不做。列宽在 430px 的面板里本来也放不下，转成一列反而更难读；表格内容按行原样显示。
- 链接不渲染成可点标签，统一写成「文字（地址）」。APK 里是 WebView，可点外链会把读者带离当前页；先保住来源信息，不引入跳转。
- 未闭合的标记按字面量显示。流式生成中途的 `**` 不会把后半段整体加粗，等闭合标记到了再变成粗体。
- 两侧带空格的星号是乘号不是强调：`3 * 5 遍` 不会被读成一段斜体。
- 围栏代码块没等到闭合时，剩下的内容仍按代码块显示，不会丢字。
- 子列表直接挂在 `li` 里，不再套一层 `ul`。多套一层会得到 `ul > ul` 这种非法结构，缩进每层多一段，读屏还会当成空列表。
- 流式光标挂在最后一个块的末尾，整个气泡始终只有一个；内容只有空白或空引用时也保底显示它。
- 嵌套解析有八层上限。服务地址是用户可配置的，模型可能被换成返回病态嵌套的服务；
  解析抛异常时发生在 render 里，而全站没有 error boundary，超限内容按文字收下，不让页面白屏。
- 引用核查前先剥掉引文里的行内标记，`「**上善若水**」` 不会因为多了两个星号被判成编造，提示文案里也不会露出 `**`。

## 流式输出

回答按 SSE 逐段渲染，不再等整段返回。

- 解析只取 `delta.content`。DeepSeek 把思考过程放在 `delta.reasoning_content`，
  那是草稿，不显示在界面上；联网时还有 `server_tool_calls` 与 `annotations`，同样忽略。
- 网络分块不按事件边界切，一个 `data:` 行可能被拆成两次收到，所以要在缓冲区里凑满空行再解析。
- 超时在流式下是「多久没收到任何数据」，不是总时长。用总时长会把正常的长回答掐断。
- 网关可能忽略 `stream` 参数照旧返回整段 JSON，按响应内容分流，不靠参数猜。
- 读者点停止时，已经显示出来的部分保留，标注「已停止生成」，并且**不做引用核查**：
  半截回答的断句会被判成「引文有问题」，那是噪音。

真机实测（deepseek-flash，430px 宽度）：字数按 5 → 4 → 90 → 123 逐步增长，
生成中显示闪烁光标，结束后光标消失。

## 存储

| 内容                             | 位置                                | 是否进备份 |
| -------------------------------- | ----------------------------------- | ---------- |
| 服务地址、模型名、密钥、省流开关 | `localStorage` 的 `daodejing.ai.v1` | 否         |
| 当前会话                         | 内存                                | 否         |
| 回答缓存                         | 不做                                | 否         |

会话只活在内存里：刷新或离开页面就没了，关闭面板再打开仍在，方便中途回章页核对原文。
落盘要额外处理加密、清理与配额，而这段对话并不值得，也违背「不把读者问过什么写进备份」这条约束。

不放进 `AppData` 是硬约束。`src/lib/store.ts` 的 `exportData()` 会把整个 state 序列化进备份 JSON，
密钥与会话一旦进去，用户分享备份就等于分享了密钥和自己问过什么。

不做本地回答缓存是刻意的简化：少一个键、少一套淘汰策略，也不用和 2.3 万字学习数据抢 localStorage 配额。

## 隐私

- 只发送读者在当前输入框里当场输入的内容。
- 绝不自动带上 `practice[n].text`。那是读者自己写的两千字笔记，是这个应用里最私密的数据。
- 密钥只存在本机，只发往读者自己配置的地址，不经过任何中转服务。
- 界面不再常驻隐私说明：面板底部那行文案会占掉拇指区，边界改由「我的」页与本文档交代，代码层面由上面两条保证。

## 错误与降级

错误归一化为七类，调用方按 `kind` 决定文案，不解析字符串。

| kind             | 触发条件                     | 兜底                                               |
| ---------------- | ---------------------------- | -------------------------------------------------- |
| `not-configured` | 地址、模型或密钥缺一项       | 引导去设置。章页本来就摆着注释，面板里不再重复一遍 |
| `offline`        | `navigator.onLine === false` | 用本地检索列出相关章节                             |
| `auth`           | 401、403                     | 提示密钥失效，直达设置                             |
| `quota`          | 402、429                     | 提示额度或频率受限                                 |
| `timeout`        | 超过 30 秒                   | 提示可重试，保留已输入内容                         |
| `parse`          | 响应不是预期结构             | 提示返回格式异常                                   |
| `network`        | 其他 HTTP 状态或请求失败     | 用本地检索列出相关章节                             |

读者主动取消返回 `aborted`，不算错误，不显示提示。

兜底路径本身要有用，否则单入口就是单点失败。

兜底检索不能用 `searchChapters`：它按空白切词，而读者的提问是一整串，「上善若水是什么意思」只会被当成一个词，命中不了任何章节。
`fallbackChapters` 换成用提问里的三字窗口去原文里扫，命中次数最多的章节排前面；一条都对不上时退回当前章。纯本地运算，不联网。

## 模块

| 文件                            | 职责                             |
| ------------------------------- | -------------------------------- |
| `src/lib/ai.ts`                 | 配置读写、请求、超时、错误归一化 |
| `src/lib/aiContext.ts`          | 消息装配、种子问题               |
| `src/lib/aiCitations.ts`        | 引用抽取与校验                   |
| `src/lib/aiMarkdown.ts`         | 回答的最小 Markdown 解析         |
| `src/hooks/useAiChat.ts`        | 会话状态、发送、取消、清空       |
| `src/components/AiPanel.tsx`    | 抽屉与弹层                       |
| `src/components/AiMarkdown.tsx` | 把回答的节点树渲染成元素         |

前四个是纯函数，不依赖 DOM，也不依赖真实网络，全部可单测。

配置用 `useSyncExternalStore` 订阅，所以不需要在 effect 里回写状态；
在设置页填完密钥回到章页，面板立刻可用，不必刷新。

## 不做的

- 端侧模型。首启下载 GB 级，与「装上就能用」冲突。
- AI 生成或改写章文、译文、注释。违反底本约定，且没有测试能判对错。
- AI 直接写 SRS 间隔或学习记录。`store.ts` 是唯一事实源，不引入不可复现的状态。
- AI 自动写践行笔记，或给实践打「道德分」。
- 语音背诵识别。安卓 WebView 的语音识别依赖 Google 服务，国内机型不可用。

## 平台差异

浏览器里直连模型服务需要对方放行跨域。DeepSeek、OpenAI、Moonshot 的 `/chat/completions` 都会回显 Origin 并允许 `authorization` 头。

APK 里的页面源是 `http://localhost`，同样需要对方放行。真机验证时要单独确认这一条；
若被拒绝，代码层面可以用 Capacitor 的 `CapacitorHttp` 让请求走原生，代价是它会全局改写 `fetch`，非必要不启用。
