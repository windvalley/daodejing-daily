# AI 助手「问道」

这份文档说明 AI 功能的边界、数据流向与实现位置。
功能本身是可选的：不配置就用不了，配置之后也不影响离线阅读、背诵与复习。

## 定位

全站只有一个入口，叫「问道」。它回答三类问题：

- 这一章某句怎么理解，某个字为什么这样读。
- 这一章和另一章、某个核心概念是什么关系。
- 这一章的内容放到具体的处境里，可以怎么做。

入口不新增路由。桌面在侧栏底部，窄屏在底栏上方悬浮。
不单独开一个 `/ask` 页面的原因有两个：做成路由会丢掉「当前停在哪一章」，也会打断朗读、默写这些带状态的页面。

## 上下文

模型拿到的材料分两层。

| 层 | 内容 | 位置 | 规模 |
| --- | --- | --- | --- |
| 全书 | 八十一章的章题、原文、章旨、译文、注释、实践提示 | system | 约 2.3 万字 |
| 焦点 | 当前章节号、选中句、该句逐字注音与释义 | 末条 user | 几十到几百字 |

全书放进 system 而不是「只发当前章」，有三个理由。

1. 跨章提问是正常用法。概念页里「德」关联二十六章，读者一定会问「这和第 8 章的水是不是一回事」。只给当前章，模型不会承认自己没材料，它会用训练记忆补一个听起来合理的答案。
2. 固定前缀能命中厂商的上下文缓存。按章换前缀等于每次都全价。
3. 全书都在前缀里，不需要检索层，省掉召回排序与「检索漏了」这一整类问题。

代价是首次请求约 70KB 上行。设置里给一个「省流模式」，打开后只发当前章与所引概念的章节，默认关闭。

## 提示词约束

写进 system，作为常量 `AI_RULES`，可被测试断言。

- 材料分级：全书是材料，当前章节是主材料；回答要说明依据哪一章。
- 训释分歧照实说：注释里已经并存两读的（如第 1 章「常无欲，常有欲」），必须并列呈现，不替读者裁决。
- 读音以数据为准：涉及读音时与注音数据一致，数据的 `hint` 优先。
- 长度：默认三句以内，纯文本，不堆 Markdown 标题与长清单；读者明确要求展开才放宽。
- 不确定就说不知道；不要编造章句与出处。

## 引用校验

回答里凡出现「第 N 章」或引号中的片段，抽出来用 `normalize` 去标点后，在各章原文里做子串匹配。

- 匹配成功：照常显示，章号变成可点链接。
- 匹配失败：在回答下方标注「有 N 处引文未在正文中找到」。

判定规则与 `src/test/data.test.ts` 校验概念引文一致。
引号里少于四个字、或汉字少于三个的片段不参与校验，避免把「无为」这类术语判成编造。

## 存储

| 内容 | 位置 | 是否进备份 |
| --- | --- | --- |
| 服务地址、模型名、密钥、省流开关 | `localStorage` 的 `daodejing.ai.v1` | 否 |
| 当前会话 | 内存 | 否 |

会话只活在内存里：刷新或离开页面就没了，关闭面板再打开仍在，方便中途回章页核对原文。
落盘要额外处理加密、清理与配额，而这段对话并不值得，也违背「不把读者问过什么写进备份」这条约束。
| 回答缓存 | 不做 | 否 |

不放进 `AppData` 是硬约束。`src/lib/store.ts` 的 `exportData()` 会把整个 state 序列化进备份 JSON，
密钥与会话一旦进去，用户分享备份就等于分享了密钥和自己问过什么。

不做本地回答缓存是刻意的简化：少一个键、少一套淘汰策略，也不用和 2.3 万字学习数据抢 localStorage 配额。

## 隐私

- 只发送读者在当前输入框里当场输入的内容。
- 绝不自动带上 `practice[n].text`。那是读者自己写的两千字笔记，是这个应用里最私密的数据。
- 密钥只存在本机，只发往读者自己配置的地址，不经过任何中转服务。
- 界面在发送按钮旁常驻一句说明，讲清这一条，不做一次性弹窗。

## 错误与降级

错误归一化为七类，调用方按 `kind` 决定文案，不解析字符串。

| kind | 触发条件 | 兜底 |
| --- | --- | --- |
| `not-configured` | 地址、模型或密钥缺一项 | 引导去设置。章页本来就摆着注释，面板里不再重复一遍 |
| `offline` | `navigator.onLine === false` | 用本地检索列出相关章节 |
| `auth` | 401、403 | 提示密钥失效，直达设置 |
| `quota` | 402、429 | 提示额度或频率受限 |
| `timeout` | 超过 30 秒 | 提示可重试，保留已输入内容 |
| `parse` | 响应不是预期结构 | 提示返回格式异常 |
| `network` | 其他 HTTP 状态或请求失败 | 用本地检索列出相关章节 |

读者主动取消返回 `aborted`，不算错误，不显示提示。

兜底路径本身要有用，否则单入口就是单点失败。

兜底检索不能用 `searchChapters`：它按空白切词，而读者的提问是一整串，「上善若水是什么意思」只会被当成一个词，命中不了任何章节。
`fallbackChapters` 换成用提问里的三字窗口去原文里扫，命中次数最多的章节排前面；一条都对不上时退回当前章。纯本地运算，不联网。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/lib/ai.ts` | 配置读写、请求、超时、错误归一化 |
| `src/lib/aiContext.ts` | 消息装配、种子问题 |
| `src/lib/aiCitations.ts` | 引用抽取与校验 |
| `src/hooks/useAiChat.ts` | 会话状态、发送、取消、清空 |
| `src/components/AiPanel.tsx` | 抽屉与弹层 |

前三个是纯函数，不依赖 DOM，也不依赖真实网络，全部可单测。

配置用 `useSyncExternalStore` 订阅，所以不需要在 effect 里回写状态；
在设置页填完密钥回到章页，面板立刻可用，不必刷新。

## 不做的

- 端侧模型。首启下载 GB 级，与「装上就能用」冲突。
- AI 生成或改写章文、译文、注释。违反底本约定，且没有测试能判对错。
- AI 直接写 SRS 间隔或学习记录。`store.ts` 是唯一事实源，不引入不可复现的状态。
- AI 自动写践行笔记，或给实践打「道德分」。
- 语音背诵识别。安卓 WebView 的语音识别依赖 Google 服务，国内机型不可用。

## 平台差异

浏览器里直连模型服务需要对方放行跨域。DeepSeek、OpenAI、Moonshot 的 `/chat/completions` 都会回显 Origin 并允许 `authorization` 头。

APK 里的页面源是 `http://localhost`，同样需要对方放行。真机验证时要单独确认这一条；
若被拒绝，代码层面可以用 Capacitor 的 `CapacitorHttp` 让请求走原生，代价是它会全局改写 `fetch`，非必要不启用。
